# 📰 Конструктор дайджестов КОС v2.5

Локальное приложение для одного человека, которое автоматически собирает корпоративные дайджесты. Умеет два типа дайджеста, выбираются переключателем на стартовом экране сайта:

1. **«Главные новости КОС»** — из постов за 2 недели. LLM предлагает классификацию, отбор и формулировки, а детерминированные правила проверяют рубрики, цифры, цитаты, дубли и соответствие исходнику.
2. **«Кадровые изменения и назначения»** — из списка людей (кто назначен, кто пришёл, кто перешёл, кто ушёл). LLM дописывает био/поздравления по коротким заметкам HR. Раздел, в который попадает человек, указывается вручную в Excel.

Результат в обоих случаях — `.htm`-файл, который копируется в Outlook одним движением.

## Редактор выпуска в v2.5

- Загружайте выгрузку портала напрямую: «Текст поста» и «Текст оригинального поста» теперь сохраняются вместе без дублирования. Поддерживаются числовые даты Excel и даты `ДД.ММ.ГГГГ`.
- Перед генерацией выберите дату выпуска, до четырех обязательных главных новостей и посты, которые не нужно включать. Можно сохранить исходные заголовки главных новостей; если отдельного заголовка в Excel нет, модель подготовит фактический.
- Модель объясняет выбор рубрики и приводит опору из исходника. Такой выбор больше не заменяется подсчетом случайных слов об оборудовании, обучении или встречах. Колонка `rubric` / «Рубрика» задает приоритетное решение редактора. Полное название «Производственная система СИБУРа» также принимается как ПСС.
- Максимум карточек в рубрике выбирается в интерфейсе (по умолчанию три). Посты не переносятся в чужую тему ради одинакового числа карточек; исключенные материалы показаны с причиной.
- Заголовки рубрик строятся через устойчивые выражения, метафоры, культурные отсылки и конкретные детали. В редакторе можно выбрать проверенную альтернативу и увидеть объяснение идеи. «Другой заголовок» учитывает согласованную подводку и избегает предыдущих вариантов.
- Для главных новостей действует отдельное правило: ясный факт, число и текущий статус вместо обязательного каламбура. Для рубрики обратной связи подводки описывают изменение без противопоставления «вы – мы».
- Дата выпуска передается на все этапы. Явно просроченные анонсы и регистрации исключаются до вызова модели; неоднозначные даты и смешанные посты остаются с предупреждением. Прошедший анонс не превращается в выдуманный отчет.
- Ссылки на запись, опрос и исходный пост сохраняют свои адреса. Придуманные адреса модель подставить не может.

Проверки помогают редактору, но не доказывают смысловую точность автоматически. Дословная опора показывает происхождение идеи; уместность метафоры и сложные условия участия нужно сверить с исходником. Пять вариантов запрашиваются у модели, в интерфейсе остаются только прошедшие проверки. Если вариантов нет или API недоступен, приложение использует фактический фрагмент и показывает замечание. Неоднозначные сроки вроде «завтра» требуют ручной проверки.

### Проверка изменений без API-ключа

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python test_smoke.py
```

Регрессионные сценарии находятся в `tests/`: чтение выгрузки, рубрики, даты, закрепленные новости, числа, ссылки, заголовки и редактор Streamlit. Они используют вымышленные посты и подмену ответа модели. Для оценки редакторского качества на выбранной модели нужен отдельный прогон реального выпуска с настроенным API. Устаревший `test_pipeline_rules.py`, ссылавшийся на удаленные функции прежнего пайплайна, заменен этими проверками.

## Что изменилось в v2.2

- Все восемь рубрик синхронизированы между кодом и промптами, включая «ВЫ ПРОСИЛИ — МЫ СДЕЛАЛИ».
- Рубрики больше не заполняются искусственно: пустые разделы не выводятся, пост остается в своей главной теме.
- Посты «ВЫ ПРОСИЛИ — МЫ СДЕЛАЛИ» не растворяются в «Главном», а остаются в рубрике обратной связи.
- Дайджест отбирает значимые новости, а не принудительно возвращает всю ленту.
- Анонс исключается, если в наборе уже есть отчет по тому же событию.
- «Главная цифра» создается только из подтвержденного значения исходного поста.
- Числа, цитаты и ссылки проходят проверку; неподтвержденная формулировка заменяется фактическим фрагментом.
- По умолчанию включен фильтр публикаций за 14 дней относительно даты выпуска.
- В редакторе видны исключенные посты, причины отбора и исходный текст каждой карточки.

## Что изменилось в v2.3

- Подводки сверены с эталонным выпуском: обычный диапазон – 180–360 знаков, ориентир – около 240.
- Содержательный исходник больше не сжимается до одной фразы: карточка раскрывает факт, деталь и результат в 2–3 предложениях.
- Короткие исходники не раздуваются общими словами.
- Фактические проверки цифр, имен, цитат и ссылок сохранены.

## Что изменилось в v2.4

- Для каждой новости модель конструирует пять заголовков разными приемами: через результат, деталь, пользу, героя и уместную игру слов.
- Код отбрасывает кликбейт, универсальные корпоративные лозунги, неподтвержденные числа и слишком длинные варианты, затем выбирает самый конкретный заголовок.
- Отдельная проверка не дает превратить план или незавершенный процесс в готовый результат: например, «планируют запустить» не станет «запустили».
- В редакторе появилась кнопка «Другой заголовок»: она обновляет заголовок, не меняя уже согласованную подводку.

## Установка (один раз)

### Шаг 1. Проверить Python

Открыть командную строку (`Win + R` → введите `cmd` → Enter), ввести:

```
python --version
```

Нужна версия **3.10 или выше**. Если её нет — установить с https://www.python.org/downloads/
**Важно:** при установке поставьте галочку **«Add Python to PATH»**.

### Шаг 2. Распаковать архив

Распакуйте `kos_digest_v2.zip` в удобную папку, например:
```
C:\Users\Ваше_Имя\Documents\kos_digest\
```

### Шаг 3. Установить зависимости

В командной строке перейдите в папку проекта и установите библиотеки:

```
cd C:\Users\Ваше_Имя\Documents\kos_digest
pip install -r requirements.txt
```

Установка займёт 1–2 минуты.

### Шаг 4. Указать API-ключ

1. В корне проекта найдите файл `.env.example`
2. Сделайте его копию и переименуйте в `.env` (без расширения `.example`)
3. Откройте `.env` в Блокноте
4. Впишите ключ от LLM-посредника:

```
OPENAI_API_KEY=sk-ваш_ключ_тут
OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1
OPENAI_MODEL=gpt-4o
```

**Примеры base_url для популярных посредников:**
- ProxyAPI: `https://api.proxyapi.ru/openai/v1`
- VseGPT: `https://api.vsegpt.ru/v1`
- AITunnel: `https://api.aitunnel.ru/v1/`
- OpenAI напрямую: `https://api.openai.com/v1`

### Шаг 5. Smoke-test

Проверим, что всё установлено правильно:

```
python test_smoke.py
```

Если в конце выведено `🎉 OK — приложение работает` — всё готово. Можно работать.

## Использование (каждый выпуск)

### Шаг 0. Выбрать тип дайджеста

При запуске (`streamlit run app.py`) сайт сначала показывает экран выбора: **«Дайджест КОС»** или **«Дайджест назначений»**. Кнопка «← сменить тип дайджеста» в сайдбаре в любой момент возвращает на этот экран. Дальше в этом разделе описан сценарий для дайджеста новостей — сценарий для дайджеста назначений см. в разделе [«Дайджест кадровых назначений»](#дайджест-кадровых-назначений) ниже.

### Шаг 1. Подготовить Excel с постами

В папке `sample_input/` есть `posts.xlsx` с шапкой. По его аналогии заполните данные:

| Колонка | Что | Обязательная? | Пример |
|---|---|---|---|
| `date` | Дата публикации | нет | `2026-05-09` |
| `author` | Автор/спикер | нет | `Татьяна Щербакова, химик ЦЗЛ` |
| `title` | Заголовок поста с портала | нет | `Дефекты в полиэтилене` |
| `text` | **Полный текст поста** | **да** | (целиком, как на портале) |
| `link` | Ссылка на портал | нет | `https://social.sibur.ru/log/298137` |
| `image_file` | **Имя файла фото** | нет | `PHOTO-12345.jpg` |

**Совет:** удобно заполнять по очереди — открыли портал, скопировали текст, ссылку, сохранили фото в папку, написали имя в `image_file`. На 30 постов уходит 30–40 минут.

### Шаг 2. Подготовить папку с фотографиями

Сложите все фотографии в одну папку, например:
```
C:\Users\Ваше_Имя\Pictures\digest_may\
```

Имена должны **в точности** совпадать с тем, что вы написали в `image_file` (расширение учитывается). Регистр (большие/маленькие буквы) не важен.

### Шаг 3. Запустить приложение

В командной строке:
```
cd C:\Users\Ваше_Имя\Documents\kos_digest
streamlit run app.py
```

Откроется браузер с интерфейсом. Если не открылся сам — скопируйте адрес из консоли (обычно `http://localhost:8501`).

### Шаг 4. Сгенерировать дайджест

В боковой панели слева:

1. **Загрузите Excel** с постами (кнопка «Browse files»)
2. **Укажите путь** к папке с фотографиями (полный путь, например `C:\Users\Имя\Pictures\digest_may`)
3. **Укажите папку** для сохранения результата (по умолчанию `output/`)
4. **Выберите дату** выпуска
5. **Кэш** — оставьте включённым (так быстрее)
6. **Debug-режим** — включите при первом запуске, чтобы видеть промежуточные данные
7. Нажмите **🚀 Сгенерировать черновик**

Через 1–2 минуты внизу появится превью дайджеста.

### Шаг 5. Проверить и поправить

В превью каждый блок можно развернуть кнопкой «Редактировать»:
- **Главные новости** — изменить заголовок, заменить фото
- **Главная цифра** — поменять число и описание
- **Главное видео** — заголовок, описание, обложку
- **Цитата** — текст, автора, должность, фото, в какую рубрику ставить
- **Карточки рубрик** — заголовок (КАПСОМ), текст, фото, флаг «с фото / без»

Для карточки рубрики есть **🎲 Перегенерировать** — LLM предложит новый заголовок и текст, после чего они снова пройдут фактическую проверку. Используйте, если первый вариант получился пресным.

### Шаг 6. Выгрузить .htm

Внизу страницы нажмите **📥 Собрать .htm**. В папке `output/` появится:
```
digest_2026-05-12.htm           ← главный файл
digest_2026-05-12.files\         ← папка с картинками
    banner.png
    main_PHOTO-12345.jpg
    card_PHOTO-67890.jpg
    rubric_production.png
    ...
```

### Шаг 7. Вставить в Outlook

1. Откройте `digest_2026-05-12.htm` в браузере (двойной клик)
2. Выделите всё (`Ctrl+A`)
3. Скопируйте (`Ctrl+C`)
4. В Outlook создайте новое письмо, поставьте курсор в тело и вставьте (`Ctrl+V`)
5. Картинки подтянутся автоматически (они в папке `.files` рядом)

## Дайджест кадровых назначений

Второй тип дайджеста — по образцу писем «Кадровые изменения и новые назначения». Вместо рубрик новостей — карточки людей, вручную разложенные по 4 разделам письма:

| Раздел (значение `section` в Excel) | Заголовок в письме | Что показывается |
|---|---|---|
| `key` | В фокусе: ключевые назначения | Фото, ФИО, новая/предыдущая должность, абзац про образование и карьерный путь |
| `new_faces` | Новые лица | То же самое, но для людей, пришедших извне компании |
| `new_challenge` | Новый вызов в СИБУРе | Фото, ФИО, новая должность + тёплое поздравление (человек перешёл в другую структуру СИБУРа) |
| `departed` | Кто ушёл из команды? | Просто ФИО + должность (без фото), иногда с личным прощанием (например, уход на пенсию), в конце — общий абзац благодарности |

### Формат Excel

Шаблон — `sample_input/appointments.xlsx`. Колонки:

| Колонка | Что | Обязательная? | Пример |
|---|---|---|---|
| `name` | ФИО | **да** | Иванов Пётр Сергеевич |
| `new_position` | Новая должность | да (кроме `departed`, где допустима прежняя) | Директор по производству |
| `section` | Раздел: `key` / `new_faces` / `new_challenge` / `departed` (принимаются и русские варианты: «ключевые», «новые лица», «новый вызов», «ушли») | **да** | key |
| `previous_position` | Предыдущая должность | нет | Заместитель директора |
| `notes` | Короткие заметки HR: вуз, специальность, карьерный путь. По ним LLM пишет абзацы био/поздравления | нет, но без них текст карточки будет пустым | Окончил КНИТУ... С 2010 года на КОС... |
| `image_file` | Имя файла фото (для `departed` не используется) | нет | photo_ivanov.jpg |
| `is_retirement` | Уход на пенсию — влияет на тон прощального текста в `departed` | нет | да |
| `order` | Порядок карточки внутри раздела (если не задан — порядок строк в Excel) | нет | 1 |

LLM вызывается **один раз на человека** (не батчами, как в новостном дайджесте) и пишет:
- `key`/`new_faces` — два абзаца: образование и карьерный путь;
- `new_challenge` — одно поздравление с переходом;
- `departed` — короткое личное прощание, **только если** заполнены `notes` или `is_retirement` (иначе в письме просто ФИО + должность без текста).

Тон и примеры настраиваются в `prompts/appointments_bio.txt` — так же, как `prompts/rewrite.txt` для новостного дайджеста.

### Как собрать

1. На стартовом экране выберите «Дайджест назначений».
2. В сайдбаре загрузите Excel (по формату выше) и фотографии людей.
3. Укажите период выпуска (даты «с» и «по» — автоматически соберутся в фразу вроде «с 1 февраля по 30 апреля 2026 г.») и, при необходимости, ссылку на PDF со схемой оргструктуры и контактный e-mail для подвала письма (в разделе «Расширенные»).
4. Нажмите «Сгенерировать дайджест» — LLM допишет тексты по разделам.
5. В редакторе поправьте ФИО/должности/фото/тексты, при необходимости нажмите «Перегенерировать» у конкретного человека или перенесите его в другой раздел.
6. «Показать предпросмотр» → «Собрать и скачать» — получите ZIP с `appointments_YYYY-MM-DD.htm` и папкой `.files`, вставляется в Outlook так же, как обычный дайджест (см. Шаг 7 выше).

## Тонкая настройка

### Поправить фирменный тон

В файле `prompts/rewrite.txt` есть **6 примеров хороших карточек** (Пример 1–6). Если фирменный тон со временем меняется (новые типичные заголовки), просто допишите туда новые примеры.

Для дайджеста назначений тон настраивается отдельно — в `prompts/appointments_bio.txt` (примеры био/поздравления/прощания по разделам).

### Поправить критерии отбора

В `prompts/plan.txt` — правила, как отбирать главные новости, цитату, видео. Можно менять.
В `prompts/classify.txt` — правила распределения по рубрикам.

### Поменять модель LLM

В `.env`:
- `gpt-4o` — лучший баланс (рекомендую)
- `gpt-4o-mini` — в 10 раз дешевле, но заголовки получаются попроще
- `gpt-4-turbo` — старая, дорогая, не используйте

### Поменять размер картинок

В `src/config.py`:
```python
SIZE_MAIN = (286, 161)    # карточка в Главном
SIZE_CARD = (265, 176)    # карточка рубрики
```

### Очистить кэш

Если хочется заставить LLM придумать всё заново на тех же данных:
- Кнопка **🗑 Очистить кэш LLM** в сайдбаре, ИЛИ
- Удалить папку `.cache/` руками

### Отключить параллелизм (если ваш посредник лимитирует RPM)

В `src/config.py`:
```python
LLM_PARALLEL_WORKERS = 1  # вместо 4
```

## Что делать, если...

**…ошибка «API-ключ не задан»**
Проверьте, что есть файл `.env` (не `.env.example`), и в нём прописан настоящий ключ, а не `sk-замените-...`.

**…ошибка «Не удалось открыть Excel»**
Закройте файл в Excel (он держит блокировку) и запустите ещё раз.

**…фотографии не появляются в готовом дайджесте**
- Проверьте, что в Excel в колонке `image_file` стоят имена файлов из вашей папки.
- Проверьте, что путь к папке с фото указан правильно в боковой панели.
- Включите Debug-режим, посмотрите `output/draft_debug.json` — там видно, доехал ли `image_file` до этапа сборки.

**…LLM выбрала не ту новость в главные**
Откройте раздел «Главное» в превью, нажмите «Редактировать» на карточке, поменяйте заголовок. Если нужно поменять сам пост — отредактируйте `plan.txt` и сделайте новый запуск.

**…карточек в рубрике мало (1–2)**
Возможно, у вас в выпуске мало постов нужной тематики. Дайджест соберётся как есть. Можно либо добавить посты в Excel, либо отредактировать промпт `plan.txt` (правило «в рубрике 2–5 карточек»).

**…цитата пустая, хочу добавить вручную**
В блоке «Цитата» есть кнопка **➕ Добавить цитату вручную**. Откроется форма для редактирования.

**…хочу другой порядок главных новостей**
Поменяйте местами заголовки руками через «Редактировать».

**…LLM пишет слишком сухие заголовки**
- Нажмите 🎲 «Перегенерировать» — будет вариант с другой температурой
- Допишите в `prompts/rewrite.txt` ваши любимые примеры заголовков из старых выпусков

**…счёт за LLM большой**
- Включите кэш (`LLM_CACHE_ENABLED=1` в `.env`)
- Используйте модель `gpt-4o-mini` (в 10 раз дешевле)
- Не запускайте дайджест на 100+ постах за раз — фильтруйте посты заранее

**…streamlit не открывает браузер**
Скопируйте адрес из командной строки (обычно `http://localhost:8501`) и откройте сами.

## Что под капотом

### Пайплайн обработки

```
Excel (30–50 постов)
       │
       ▼
ШАГ 1: Классификация
  - Небольшие батчи по 8 постов
  - Каждый пост получает: рубрику, важность, цитату, цифру, метки
  - Правила сверяют рубрику, цифры и дословность цитаты
       │
       ▼
ШАГ 2: План дайджеста
  - Один большой LLM-вызов
  - Решает: что в Главное, что в цифру, цитату, видео
  - Убирает дубли и слабые анонсы
  - Не заполняет рубрики искусственно
       │
       ▼
ШАГ 3: Перепись карточек
  - Для каждой карточки: 5 вариантов заголовка + текст 2–4 предложения
  - Выбор самого конкретного фактического заголовка
  - Проверка новых чисел, статуса новости, шаблонных фраз и связи с исходником
       │
       ▼
Сборка HTML
  - Кадрирование фото под слоты (286×161, 265×176, ...)
  - Копирование в .files-папку
  - Рендер Jinja2-шаблона
       │
       ▼
готовый .htm для Outlook
```

### Защита от типовых проблем

- **Кэш LLM:** sha1-хеш от промпта → JSON-ответ. Повторный запуск на тех же данных = 0₽
- **Retry:** до 5 попыток с экспоненциальным бэкоффом при ошибках сети/парсинга
- **Контроль нагрузки:** число параллельных запросов настраивается; в облачной версии по умолчанию один поток
- **Защита image_file:** в merge `{**classification, **post}` исходные поля Excel всегда побеждают
- **Канонический порядок рубрик:** Производство → ПСС → Безопасность → Забота → Карьера → События → Достижения → Вы просили — мы сделали; выводятся только непустые
- **Сингтоны:** один пост может попасть только в один блок (Главное / Цифра / Цитата / Видео / Рубрика)
- **Фактический барьер:** новые цифры и недословные цитаты не проходят в черновик
- **Редакторский отбор:** максимум четыре карточки в рубрике, остальные видны в списке исключенных с причиной
- **Видео ставится после ПРОИЗВОДСТВА:** жёстко, не «после первой рубрики»
- **Валидация Excel:** понятные сообщения вместо stacktrace
- **Валидация фотопапки:** проверка, что файлы из image_file существуют
